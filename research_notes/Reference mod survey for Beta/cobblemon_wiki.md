# Cobblemon wiki and published documentation as a reference for Project Nublar Beta

Scope: player-facing and designer-facing documentation only (wiki.cobblemon.com, the Cobblemon GitLab `docs/` folder, Modrinth and CurseForge listings). Source code was not read; another researcher covers it.

Reading date: every URL below was read on 2026-10-10. Labels: [doc] = stated in the cited page; [inf] = my inference from cited pages; [3rd] = third-party page, not Cobblemon documentation.

Each finding gives: in-game effect, documented rule or number, Nublar module(s) it maps to (B00-B27 or post-Beta), and whether it conflicts with vanilla Minecraft feel ("vanilla:" note).

Wiki state: the wiki Main Page features the 1.8.0 "Make Your Move Update" and was last edited 10 September 2026 [doc](https://wiki.cobblemon.com/index.php/Main_Page). The Config page was created 27 Feb 2024 and last edited 1 Feb 2026 (17 edits) [doc](https://wiki.cobblemon.com/index.php?title=Config&action=info), so it predates 1.8.0 and in one place disagrees with the 1.7.0 changelog (see Performance and config).

## Key question 1: Species and data (species JSON, spawn pool JSON, asset pipeline, datapack overrides)

### Takeaway
Cobblemon's species data is one JSON per species (`data/cobblemon/species/<group>/<name>.json`) with nested `forms`, `behaviour`, `evolutions`, `drops`, `hitbox`, `baseScale`, `features` and (since 1.7) `riding`; visual variants are a separate layer built from "features" (flag, choice, weighted_choice) that become "aspects" selected by client-side resolver JSON files. Spawning is fully data-driven through `spawn_pool_world` files with buckets, weights, contexts, conditions, anticonditions and reusable presets, and addons extend species non-destructively through `species_additions` and `species_feature_assignments`.

### Cited Findings

Species file: location, scope and loading
- [doc] One species file per Pokémon holds moves, abilities, forms, size and evolutions; a custom species goes in `data/cobblemon/species/custom/<name>.json` with a spawn file in `data/cobblemon/spawn_pool_world/<name>.json`. Maps to B00. vanilla: n/a (vanilla has no per-species data files). — [Tutorials/Creating A Custom Pokemon](https://wiki.cobblemon.com/index.php/Tutorials/Creating_A_Custom_Pokemon)
- [doc] `/reload` does not reload Cobblemon datapacks; data edits need a return to the main menu and world reload, while resource pack changes reload with F3+T. Maps to B00, B24. — [Tutorials/Creating A Custom Pokemon](https://wiki.cobblemon.com/index.php/Tutorials/Creating_A_Custom_Pokemon); same statement in [Tutorials/Multiple Visual Variants](https://wiki.cobblemon.com/index.php/Tutorials/Multiple_Visual_Variants)
- [doc] 1.7.0 made "several registries" reloadable with `/reload` (which ones is not listed). Maps to B00. — [1.7.0](https://wiki.cobblemon.com/index.php/1.7.0)
- [doc] Failure modes the tutorial warns about: an invalid egg group value crashes the game; a misspelled `experienceGroup` means the Pokémon never levels; a poser referencing a `head` bone that does not exist crashes the game; a mistyped fossil `result` species falls back to a random loaded species. Maps to B00 (Nublar's "unknown fields fail loudly" is stricter than Cobblemon's mixed crash/silent-fallback behaviour). — [Tutorials/Creating A Custom Pokemon](https://wiki.cobblemon.com/index.php/Tutorials/Creating_A_Custom_Pokemon); [Fossils File](https://wiki.cobblemon.com/index.php/Fossils_File)

Species file: documented top-level fields (from the Vulpix example)
- [doc] `implemented` (bool; controls inclusion in `/spawnallpokemon`), `name`, `nationalPokedexNumber` (not gameplay-significant; custom species advised to use a unique number above 2000), `primaryType` (secondary type optional), `abilities` (string list; up to two normal plus one hidden with `h:` prefix), `baseStats` {hp, attack, defence, special_attack, special_defence, speed}, `catchRate`, `maleRatio` (0-1; -1 = genderless), `shoulderMountable`, `baseExperienceYield`, `experienceGroup` (e.g. `medium_fast`), `eggCycles` (about 20 matches a starter egg), `eggGroups`, `baseFriendship` (most use 50), `evYield` (same six keys), `height` (decimetres), `weight` (hectograms; used by weight-based moves), `moves` (`method:movename`; methods `level`, `egg`, `tm`, `tutor`; only level is implemented), `labels`, `pokedex` (lang keys), `aspects` (visual variant tags; default form uses `[]`), `features` (feature names that create aspects), `forms[]`, `evolutions[]`, `drops`, `baseScale` (1 = Blockbench size), `hitbox` {width, height, fixed}, `cannotDynamax`, `lightingData` {lightLevel 0-15, liquidGlowMode LAND/UNDERWATER/BOTH}, `shoulderEffects[]`. Maps to B00, B16 (stats, scale, hitbox), B09 (aspects), B17 (diet has no equivalent here). vanilla: n/a. — [Species](https://wiki.cobblemon.com/index.php/Species)
- [doc] `maleRatio` 0 makes a species female-only, -1 genderless. Maps to B07/B18 (sex as a categorical gene). — [Tutorials/Creating A Custom Pokemon](https://wiki.cobblemon.com/index.php/Tutorials/Creating_A_Custom_Pokemon)
- [doc] `forms[]` entries repeat the species structure (name, types, abilities, baseStats, catchRate, maleRatio, yields, experienceGroup, eggCycles, eggGroups, moves, labels, aspects, height, weight, evolutions, `battleOnly`); a form only applies if its name is listed in the species `features`. Maps to B09 (biome skin variants with stat differences), B00. — [Species](https://wiki.cobblemon.com/index.php/Species)
- [doc] `evolutions[]` entries: `id`, `variant` (e.g. `item_interact`), `result` (supports `ninetales form=alola`), `consumeHeldItem`, `learnableMoves`, `requirements[]`, `requiredContext` (item id). Maps to post-Beta (Nublar has growth, not evolution); the `requirements` pattern is a model for B16 growth gates. — [Species](https://wiki.cobblemon.com/index.php/Species)
- [doc] `drops`: `amount` (target number of successful drops) and `entries[]` of `item` plus `quantityRange` (e.g. "2-3") and a percentage that defaults to 100 when omitted; 1.8.0 added data-component support to species drops. Maps to B00, B16. — [Species](https://wiki.cobblemon.com/index.php/Species); [1.8.0](https://wiki.cobblemon.com/index.php/1.8.0)
- [doc] Sizing (1.8.0): every Pokémon gets slight intrinsic scaling of about 5 percent smaller to 5 percent bigger; baby Pokémon scale from 10 percent smaller at level 1 to normal size at level 10; some cases such as shoulder mounts do not scale. Maps to B16 (smooth growth, scaled hitbox), B09 (render scale), B07 (size variation per clone). vanilla: conflicts mildly; vanilla mobs have fixed adult size except slimes and babies. — [1.8.0](https://wiki.cobblemon.com/index.php/1.8.0)
- [doc] Debug commands exist to tune sizing live: `/changescaleandsize <species> <scale> [<width> <height>]`, `/changeeyeheight <species> <standing|flying|swimming> <eyeheight>`, `/changewalkspeed <species> <walkspeed>`; each is temporary and needs Pokémon recalled afterwards. Maps to B00, B16 (a model for a Nublar debug stick). — [Commands](https://wiki.cobblemon.com/index.php/Commands)

Behaviour block (species JSON `behaviour`)
- [doc] Default AI with no behaviour block: a land-moving AI at a brisk pace that cannot breathe underwater and does not sleep. Maps to B16, B17. — [Pokémon/Behaviour](https://wiki.cobblemon.com/index.php/Pok%C3%A9mon/Behaviour)
- [doc] `moving.walk`: `canWalk`, `avoidsLand`, `walkSpeed` (default 0.35). `moving.swim`: `avoidsWater`, `canSwimInWater`, `canBreatheUnderwater` (default false; drowns if submerged too long), `canWalkOnWater`, `canSwimInLava`, `canBreatheUnderlava` (default false), `canWalkOnLava`, `hurtByLava`, `swimSpeed` (default 0.3). `moving.fly`: `canFly`, `flySpeedHorizontal` (default 0.3). Other `moving` keys: `canLook`, `looksAtEntities` (default true), `stepHeight` (blocks, default 0.6; page says it does not work properly because pathfinding is unfinished), `wanderChance` (ticks, default 120), `wanderSpeed` (multiplier, default 1; very high values may change pathfinding). Maps to B16 (movement stats), B00. vanilla: speeds are in vanilla movement-speed units (0.35 is faster than a vanilla cow at 0.2) [inf]. — [Pokémon/Behaviour](https://wiki.cobblemon.com/index.php/Pok%C3%A9mon/Behaviour)
- [doc] `resting`: `canSleep` (gate for all other sleep filters), `times` (default "night"; accepts names like day/dawn/dusk/morning, tick ranges like "1200-2400", comma-combined), `sleepChance` (per tick, default 0.0017, roughly 30 seconds on average), `blocks` (block ids or tags it may sleep on), `biomes`, `light` ("15" or "0-7"), `depth` ("normal" wakes when a non-sneaking player is within 16 blocks; "comatose" sleeps through nearly anything; custom depths via SleepDepth API), `willSleepOnBed` (sleeps on the player's bed when the player gets in, like cats). Maps to B17 (sleep need), B19 (detection by sight/sound: the 16-block non-sneaking wake rule is a documented detection threshold). vanilla: sleeping mobs conflict with vanilla (only villagers and cats sleep); bed behaviour copies vanilla cats. — [Pokémon/Behaviour](https://wiki.cobblemon.com/index.php/Pok%C3%A9mon/Behaviour)
- [doc] The Behaviour page documents only `moving` and `resting`; no `herd`, `idle`, `combat` or `entityInteract` fields are documented anywhere on the wiki. Maps to B18. — [Pokémon/Behaviour](https://wiki.cobblemon.com/index.php/Pok%C3%A9mon/Behaviour)
- [doc] 1.7.0 rebuilt Pokémon AI on Minecraft's Brain system, added a `behaviours` datapack folder, and a Behaviour Editor GUI opened with `/behaviouredit` for NPCs and Pokémon (editing Pokémon variables not yet supported). Maps to B16, B18, B21. — [1.7.0](https://wiki.cobblemon.com/index.php/1.7.0)

Visual variants: features, aspects, resolvers (datapack side)
- [doc] Species features live in a `species_features` folder; each feature creates one or more aspects, which get assets in resolver files, and stats via `forms`. Types: `flag` (`keys`, `type`, `isAspect` usually true, `default` usually false; used for regional forms) and `choice` (`keys`, `type`, `default` "random"/true/false with "random" recommended, `choices[]`, `isAspect` always true, `aspectFormat` such as `pumpkin-size-{{choice}}`). Combining pools of different features multiplies the variant count (Alcremie `cream` x `decoration`; Arbok `snake_pattern` with 8 choices). Maps to B09 (morphs, colour genes, biome skins), B07 (categorical genes). vanilla: n/a. — [Species Features](https://wiki.cobblemon.com/index.php/Species_Features)
- [doc] 1.8.0 added feature type `weighted_choice` with per-choice weights (the documented route to a "5 percent morph"). Maps to B09. — [1.8.0](https://wiki.cobblemon.com/index.php/1.8.0)
- [doc] With no aspect specified, the feature `default` applies and "random" picks a choice; a spawn entry whose `pokemon` string includes an aspect (e.g. `arbok snake-pattern=classic`) forces that choice; evolution keeps the aspect when the whole line has the feature, and evolution data can set the next aspect. Maps to B09, B18 (inheritance hook), B00. — [Tutorials/Multiple Visual Variants](https://wiki.cobblemon.com/index.php/Tutorials/Multiple_Visual_Variants)
- [doc] Three ways to attach a feature: `"features": [...]` in the species file; a `species_additions` file with `target`, `features`, `forms`; or a `species_feature_assignments` file with only `pokemon[]` and `features[]` (every listed feature applied to every listed Pokémon; a misspelled folder name silently invalidates the files). Maps to B00, B09. — [Species Features](https://wiki.cobblemon.com/index.php/Species_Features); [Species Feature Assignments](https://wiki.cobblemon.com/index.php/Species_Feature_Assignments)

Datapack overrides: species additions
- [doc] `species_additions/<file>.json` targets an existing species (`target: "cobblemon:bulbasaur"`) and adds or replaces data without overwriting the base file; documented fields: `primaryType`, `secondaryType`, `shoulderMountable`, `shoulderEffects`, `drops`, `behaviour`, `baseScale`, `hitbox`, `lightingData`, `forms`, `evolutions`, `features`. Most fields override whole; lists are replaced whole (to add one move you restate the list); `forms` and `evolutions` always append; when two additions rewrite the same field, the first in load order wins. Use your own namespace to avoid collisions. 1.8.0 made append/override behaviour match this documentation. Maps to B00 (override semantics for Nublar species files), B24 (artists adjusting `baseScale`/`hitbox` without touching the base file). — [Species Additions](https://wiki.cobblemon.com/index.php/Species_Additions); [1.8.0](https://wiki.cobblemon.com/index.php/1.8.0)

Spawn pool JSON (`spawn_pool_world`)
- [doc] File top level: `enabled`, `neededInstalledMods`, `neededUninstalledMods`, `spawns[]`. Entry: `id` (unique, e.g. `bulbasaur-1`), `pokemon` (species, may carry properties), `presets[]`, `type` (`pokemon`), `context` (`grounded`, `submerged`, `surface`; examples also use `fishing`), `bucket` (`common`, `uncommon`, `rare`, `ultra-rare`), `level` ("5-32"), `weight` (relative within bucket; guidance scale about 0.1 to 10, higher allowed), `weightMultiplier` {multiplier, condition}, `condition`, `anticondition`. Example weights: Bulbasaur ultra-rare 9.0 at level 5-32; Buneary common 5.4 with sky light 8-15; Klink common 9.0 (and 1.8 variant) with sky light 0-7; Elekid uncommon base 1.8 with multiplier 5.0. The page states Bulbasaur as an ultra-rare "occurs 0.2% of the time" but gives no bucket percentage table. Maps to B00 (a model for data-driven conditions), B25 (caps). vanilla: conflicts with vanilla's biome-modifier spawn model. — [Spawn Pool World](https://wiki.cobblemon.com/index.php/Spawn_Pool_World)
- [doc] Weight is relative to competition in the bucket: a low-weight entry that is the only ultra-rare in a pool spawns often. Maps to B00. — [Tutorials/Creating Custom Spawns](https://wiki.cobblemon.com/index.php/Tutorials/Creating_Custom_Spawns)
- [doc] A pack can suppress all base-mod spawns by adding a `pack.mcmeta` `filter.block` entry with namespace `cobblemon` and path `spawn_pool_world`. Spawn files must have a different file name from the base file or they replace it. Test with `/checkspawn <rarity>` at the player's position; aspects do not show in `/checkspawn`. Maps to B00. — [Tutorials/Creating Custom Spawns](https://wiki.cobblemon.com/index.php/Tutorials/Creating_Custom_Spawns); [Tutorials/Multiple Visual Variants](https://wiki.cobblemon.com/index.php/Tutorials/Multiple_Visual_Variants)
- [doc] Spawn conditions, common to all contexts (empty values are unchecked): `dimensions`, `biomes` (ids or `#tags`), `structures`, `moonPhase` (0-7), `canSeeSky` (fluids do not block), `minX/minY/minZ`, `maxX/maxY/maxZ`, `minLight/maxLight` (0-15), `minSkyLight/maxSkyLight`, `timeRange` (named ranges or tick ranges), `isRaining`, `isThundering` (thunder counts as raining too), `isSlimeChunk`, `labels` + `labelMode` (ANY/ALL). Area conditions: `minWidth/maxWidth`, `minHeight/maxHeight` (free space; prevents suffocation), `neededNearbyBlocks` (search distance from config). Grounded: `neededBaseBlocks`. Submerged: `minDepth/maxDepth`, `fluidIsSource`, `fluid`. Fishing: `minLureLevel`, `maxLureLevel`, `bobber`, `bait`. Maps to B00 (condition vocabulary for nests, feeders, hatch conditions), B11 (hatch conditions by light/biome/time) [inf]. — [Spawn Condition](https://wiki.cobblemon.com/index.php/Spawn_Condition)
- [doc] Presets are reusable bundles of `context`, `condition`, `anticondition`, named after their file in `spawn_detail_presets`; example `stronghold` = structure stronghold, maxY 62, base `#minecraft:stone_bricks`, nearby cracked/mossy stone bricks; `river` uses `#cobblemon:is_river` with anticondition `#cobblemon:is_freezing`. - [doc] The 1.8.0 preset list has 28 presets: nether_structures, water, natural (natural base blocks, excludes farmland), saccharine_tree, ocean_ruins, end_city, ancient_city, redstone, webs, pillager_outpost, foliage, illager_structures, nether_fossil, wild (excludes concrete nearby and village structures), derelict (cannot see sky, max light 0, excludes natural base blocks), ruined_portal, mansion_bedrooms, ocean_monument, trail_ruins, mansion_dining, lava, urban (near concrete), salt, treetop, mansion, desert_pyramid, jungle_pyramid, stronghold. - [doc] Biome tag guidance: `is_cold` is meant for anticonditions, not primary conditions (it spans dimensions); `is_hills` and `is_peak` are subsets of `is_mountain`; `is_beach` is sandy coast only while `is_coast` is any ocean-bordering coast; nether tags are `cobblemon/nether:is_[name]`; `cobblemon/has_block:[name]` tags exist but are fragile with biome mods. Asset pipeline (resource pack side)
- [doc] Paths: model `assets/cobblemon/bedrock/pokemon/models/<name>/<name>.geo.json`; textures `assets/cobblemon/textures/pokemon/<name>/<name>.png` (+ `<name>_shiny.png`); animations `assets/cobblemon/bedrock/pokemon/animations/<name>/<name>.animation.json`; poser `assets/cobblemon/bedrock/pokemon/posers/<name>.json`; resolver `assets/cobblemon/bedrock/pokemon/resolvers/<name>/0_<name>_base.json`; lang `assets/cobblemon/lang/en_us.json` with `cobblemon.species.<name>.name`, `.desc1`, `.desc2`. Maps to B24. — [Tutorials/Creating A Custom Pokemon](https://wiki.cobblemon.com/index.php/Tutorials/Creating_A_Custom_Pokemon); [Tutorials/Texture replacement](https://wiki.cobblemon.com/index.php/Tutorials/Texture_replacement)

Maps to B24 (artist checklist). vanilla: n/a. — [Tutorials/Creating A Model](https://wiki.cobblemon.com/index.php/Tutorials/Creating_A_Model)
- [doc] Animation naming `animation.<pokemon>.<type>`; pose-to-animation mapping: STAND `ground_idle` (also battle idle), WALK `ground_walk`, HOVER `air_idle`, FLY `air_fly`, FLOAT `water_idle`, SWIM `water_swim`, SLEEP `sleep`, SHOULDER_LEFT/RIGHT, plus `faint` and `cry`; recommended minimum set is `ground_idle`, `ground_walk`, `faint`. Maps to B24. — [Tutorials/Creating A Model](https://wiki.cobblemon.com/index.php/Tutorials/Creating_A_Model); [Tutorials/Creating A Custom Pokemon](https://wiki.cobblemon.com/index.php/Tutorials/Creating_A_Custom_Pokemon)
- [doc] Poser JSON: `rootBone`, `portraitScale`, `portraitTranslation` [x,y,z], `profileScale`, `profileTranslation`, `animations` (named events `faint`, `cry`, `recoil`, `physical`, `special`, `status`, move names) and `poses` keyed by name with `poseTypes` (STAND, NONE, PORTRAIT, PROFILE, WALK, HOVER, FLY, FLOAT, SWIM, SLEEP, SHOULDER_LEFT, SHOULDER_RIGHT), `isBattle`, `condition` (Molang, e.g. `q.is_standing_on_blocks(...)`), `namedAnimations`, `animations[]` (`q.bedrock(group, anim)`, `q.bedrock_primary(...)` with `q.curve(one|symmetric|symmetrical_wide)`, `q.look(bone, pitchMult, yawMult, maxPitch, minPitch, maxYaw, minYaw)` defaults 1,1,70,-45,45,-45, placeholders `q.quadruped_walk`, `q.biped_walk`, `q.bimanual_swing`, `q.sine_wing_flap`), `quirks[]` (`q.bedrock_quirk(group, anim, minSeconds, maxSeconds, loops)` default 8-30 s), `transformedParts[]` {part, position, rotation, isVisible}; boolean conditions include `isTouchingWater`, `isInWaterOrRain`, `isUnderWater`, `isStandingOnSand`, `isDusk`. - [doc] Resolver JSON: `species`, `order` (0 base; higher loads later), `variations[]` of `aspects[]` (`[]` = default), optional `poser`, `model` (`<name>.geo`), `texture`, `layers[]`; unspecified poser/model/texture fall back to the previous or default variation; missing texture renders purple/black; aspect order matters, "shiny" must be listed last. ### Inferences
- [inf] Cobblemon separates "what a creature is" (datapack species + features) from "what it looks like" (resource pack resolver keyed by aspect strings). Nublar's B09 colour genes and morphs could map genes to aspect strings so artists bind textures in a resolver-like JSON without code (B24).
- [inf] The `weighted_choice` feature type with `default: "random"` is the documented primitive for Nublar's "morph at about 5 percent": weight 95 base, 5 morph.
- [inf] The spawn condition vocabulary (light, sky light, time range, biome tags, nearby blocks, free width/height, fluid depth) is a ready-made schema for Nublar's data-driven conditions on nests, feeders and hatch requirements even though Nublar has no natural spawns.
- [inf] Cobblemon tolerates many typos silently (misspelled folder, misspelled experience group, wrong pack_format); Nublar's "unknown fields fail loudly" rule is a deliberate improvement over this documented pain.

### Gaps
- The wiki does not document any herd-related species fields, the `behaviours` datapack format, `idle`/`combat` behaviour keys, or the `riding` block schema beyond the tutorial examples (see Riding). Changelogs mention "herd spawn files" (Pangoro, Dedenne) and `herdLevelRange` but no page describes them.
- No bucket percentage table (common/uncommon/rare/ultra-rare) is documented; the official "spawn sheets" are a Google Drive folder I could not read.
- Drop format details (`percentage` key name, component syntax) are not on the wiki; the drops page defers to a Google Drive sheet.
- Species `riding`, `battleTheme`, `preEvolution`, `secondaryType` key names are not shown on the Species page.

## Key question 2: Riding (behaviours, controllers, stamina, stats, seats, camera, controls, data format, track-like movement)

### Takeaway
Riding (added in 1.7.0, November 2025) is saddle-free, selected via shift-right-click, and defined per species by one ride "style" per medium (land, liquid, air) plus five 0-100 stats (speed, acceleration, skill, jump, stamina) given as min-max ranges, seat locators in the model, and optional Molang-driven ride sounds; eight styles copy vanilla horse, boat, elytra or creative-flight feel. No track or path-following movement is documented.

### Cited Findings

Player experience and controls
- [doc] Players shift-right-click a Pokémon and choose the ride option; no saddle needed. Each riding style remembers the player's preferred camera mode across mount and dismount; a "Disable Roll" option exists for motion sickness; Aprijuice improves riding traits. Maps to B22 (mount interaction and camera memory), B19. vanilla: conflicts with vanilla horses which need a saddle. — [1.7.0](https://wiki.cobblemon.com/index.php/1.7.0); [Pokémon/Riding](https://wiki.cobblemon.com/index.php/Pok%C3%A9mon/Riding)
- [doc] 1.7.1 added a customisable freelook keybind, double-tap to sprint on land mounts, vanilla sprint FOV change on land mounts, and made Jet pitch turning 1.5x faster; fixed camera pivot on Bird, Jet and Dolphin mounts and ride overlay shown to passengers. Maps to B22. vanilla: adopts vanilla sprint FOV. — [1.7.1](https://wiki.cobblemon.com/index.php/1.7.1)
- [doc] Config `enableInFlightDismounting` default false (added 1.7.2) allows dismounting in the air. Maps to B22. — [Config](https://wiki.cobblemon.com/index.php/Config); [1.7.2](https://wiki.cobblemon.com/index.php/1.7.2)
- [doc] Land styles: Standard works like vanilla horse riding (mouse look steers, A/D strafe, sprint drains stamina); Vehicle works like vanilla boats (movement ignores mouse look, A/D turn, wider turning circle, hold turn plus crouch to drift). Liquid styles: Boat (free look, A/D turn), Submarine (can submerge), Dolphin (can also leap out). Air styles: Bird (look steers, strafes, forward/back or mouse push/pull for altitude; a config option switches to elytra-like control), Jet (boat-style control, cannot hover, high speed, jump/crouch to climb/descend), Hover (omnidirectional like creative flight, very slow, flying above its max height drains stamina), Rocket (Hover plus fast forward flight). A species may hold one style from each category. Maps to B22 (the Jeep is closest to "Vehicle" land style; the tour vehicle is closest to a Vehicle with no player steering). vanilla: Standard and Vehicle deliberately copy vanilla horse and boat feel. — [Pokémon/Riding](https://wiki.cobblemon.com/index.php/Pok%C3%A9mon/Riding)
- [doc] Stats (separate from battle stats): Speed = max velocity; Acceleration = time to reach max; Skill = turn rate (deceleration for Hover); Jump = jump height, plus per style: submerge/emerge speed (Submarine, Dolphin), glide effectiveness (Bird), lower take-off speed (Jet), height before stamina drain (Hover), ascent speed (Rocket); Stamina = duration of the style's special ability: sprint time (Standard), oxygen (Submarine), flight time (Bird, Jet), max height (Hover, Rocket); when stamina runs out the ability cancels and must recover. Maps to B22 (speed, acceleration, turn-rate and stamina model for the Jeep). vanilla: horses have speed and jump but no stamina. — [Pokémon/Riding](https://wiki.cobblemon.com/index.php/Pok%C3%A9mon/Riding)

- [doc] A riding behaviour entry has `key` (`cobblemon:land/horse`, `cobblemon:air/bird`, `air/jet`, `air/hover`, `air/rocket`, `liquid/boat`, `liquid/submarine`, `liquid/dolphin`), `rideSounds[]`, `stats` {ACCELERATION, JUMP, SKILL, SPEED, STAMINA} each as a "min-max" string within 0-100, `seats[]` of `{ "locator": "seat_1" }` (one entry per seat; Camerupt has six), and optional `canJump`/`canSprint` booleans. - [doc] Seat data fields: `offset` {x,y,z} general offset and `poseOffsets[]` of {poseTypes[], offset}; `/calculateseatpositions <species> <aspects> <pose>` simulates the first pose of that type, averages each seat locator's position and copies `{x,y,z}` JSON to the clipboard (example general 0,0.4,0; FLOAT/SWIM override 0,0.7,0.2). 1.8.0 cleaned up seat data, made locator seat names explicit (legacy format still works) and added conditional seats gated by Molang such as `is_alpha`. - [doc] The rideable list has 99 entries (89 land, 19 liquid, 44 air); seats range from 1 to 19 (Wailord 19, Dondozo 7, Dewgong and Dragonite 2); many entries use a shared placeholder stat block of 10-40 for everything but SKILL 80-100, while tuned entries differ (Arcanine ACCEL 70-90, Rhydon SPEED 5-15 STAM 55-90, Slaking ACCEL 0-20 STAM 60-100). Maps to B22 (multi-seat tour vehicle precedent: 19 seats on one entity). — [Template:RidingTable](https://wiki.cobblemon.com/index.php/Template:RidingTable)
- [doc] Aprijuice permanently raises a Pokémon's riding stats: apricorn colour sets base modifiers (Red +2 Accel -1 Stam; Blue +2 Skill -1 Jump; Pink +2 Speed -1 Accel; Yellow +2 Stam -1 Skill; Green +2 Jump -1 Speed; Black none; White -2 all), flavours map Spicy->Accel, Dry->Skill, Sweet->Speed, Sour->Stam, Bitter->Jump with summed flavour thresholds 15/35/45/55/75/105 giving +1 to +6; quality tiers Plain under 4 points, Tasty 4-7, Delicious 8+. - [doc] 1.8.0: hover mounts no longer suffer a block-breaking speed penalty; ride sounds can be passenger-only and do not play underwater unless enabled; fixes to submarine braking/strafing friction and bird fly/glide flicker at low speed. Maps to B22. — [1.8.0](https://wiki.cobblemon.com/index.php/1.8.0)
- [doc] Riding statistics (distance on land, air, liquid) and ride-style labels in the Pokédex and summary were added in 1.7.2. Maps to B22 (telemetry), post-Beta. — [1.7.2](https://wiki.cobblemon.com/index.php/1.7.2)

### Inferences
- [inf] Stat ranges per species imply each individual rolls a value within the range (the wiki says stats are "assigned per Pokémon by default"), which parallels Nublar's per-clone variation in B07; the exact roll rule is not documented.
- [inf] For Nublar's Jeep (B22), the Vehicle land style (boat-like steering, free look, drift with crouch) is the documented closest feel; the Standard style is a horse. For the tour vehicle on a track, nothing in Cobblemon applies.

### Gaps
- No documentation of track-, rail- or path-following movement for ridden entities; Cobblemon has none.
- The `riding` block's full schema (how `behaviours` are keyed per medium, `conditions`, `canStand`, camera settings per style, the elytra-like Bird option's key) is not documented on the wiki; only tutorial fragments exist.
- Stamina drain and recovery rates, speed units, and the mapping from 0-100 stat values to blocks per tick are not documented anywhere I read.

## Key question 3: Breeding and genetics (IVs, EVs, natures, abilities, egg groups, egg moves, shiny odds, inheritance, daycare/pasture breeding, hatching)

### Takeaway
Cobblemon 1.8.1 has no official breeding, eggs or daycare: the wiki has no breeding page, the species JSON carries `eggCycles` and `eggGroups` as unused data, the `egg` move method is unimplemented, and CurseForge lists breeding among planned features; documented genetics are limited to spawn shiny odds (1/8192 by default), per-stat IV edits of plus or minus 1 via Hyper Training candies, and Molang access to IVs and EVs.

### Cited Findings
- [doc] The CurseForge project description lists breeding among features that are planned, alongside NPCs, riding and structures. Maps to B18 (Nublar must design its own breeding; Cobblemon offers no documented model). — [CurseForge: Cobblemon](https://www.curseforge.com/minecraft/mc-mods/cobblemon)

Maps to B19 (taming/bond value). — [Config](https://wiki.cobblemon.com/index.php/Config); [Species](https://wiki.cobblemon.com/index.php/Species); [1.7.1](https://wiki.cobblemon.com/index.php/1.7.1)

### Inferences
- [inf] Cobblemon's documented aggression model is retaliation only (alphas "always defend themselves"); nothing documents unprovoked attacks on players, so Nublar's carnivore aggression and stress-driven behaviour (B17, B19) go beyond anything in these docs.
- [inf] The alpha "mini spawner" plus follower herd is the only documented herd structure: one leader, followers of the youngest stage, followers track the leader. Cobblemon does not document leader challenges, herd size caps or follow distances.
- [inf] The Habitat Block's editor fields (level range, mode, trigger, spawn range, max spawns, pool with bucket/weight/time/light modifiers) are a compact spec for a Nublar "release point" or breeding nest data block if B18 nests need a configurable spawner-like component.
- [inf] Pasture limits (16 per block, 4 per chunk, 32-64 block wander, 40-tick updates) are the documented density numbers closest to Nublar's enclosures; Nublar's B25 target of 100 dinosaurs at 20 TPS exceeds what a single pasture allows, so Nublar needs its own caps.

### Gaps
- NPC class JSON (the `npcs` datapack folder: skins, hitbox, battle config, interaction, variables) is not documented on the wiki; only commands, Molang functions, dialogue and party pools are.
- Herd data format, herd size, follow distance and leader selection beyond "alpha leads" are undocumented.
- Fullness values, interaction cooldowns, and pastured-creature AI specifics (what "approach the player" means) are undocumented.
- Spawn cycle details beyond the config keys (how buckets are rolled per attempt, how level is chosen from the player's party) are not on the wiki; `minimumLevelRangeMax` 10 is the only documented level-selection input.

## Additional documented mechanics relevant to Nublar (fossils and revival, sizing, scanning tools, commands)

### Takeaway
Cobblemon's fossil pipeline (dig sites with suspicious blocks, a three-part Resurrection Machine, a 64-point organic-material fill, a 12-minute revival, a datapack `fossils` file that maps up to three items to a result property string) is the closest documented analogue to Nublar's fossil-to-egg loop and is fully data-driven.

### Cited Findings
- [doc] Fossils come from brushing suspicious sand or gravel at Fossil Dig Site structures (23 site types across biomes; each site guarantees one fossil, with weighted uncommon and common pools replacing blocks at listed chances such as 15 percent / 25 percent); fossil items (Armor, Claw, Cover, Dome, Helix, Jaw, Old Amber, Plume, Root, Sail, Skull, Fossilized Bird/Dino/Drake/Fish) each revive a fixed species, with the four Galar fossils pairing into Dracozolt, Arctozolt, Dracovish, Arctovish. Maps to Nublar fossils module and B11 (fossil to embryo to animal). vanilla: builds on vanilla archaeology. — [Fossil](https://wiki.cobblemon.com/index.php/Fossil); [Fossil Dig Sites](https://wiki.cobblemon.com/index.php/Fossil_Dig_Sites)
- [doc] Resurrection Machine = Data Monitor + Fossil Analyzer + Restoration Tank; a correct build plays an electrical sound; the analyzer holds fossils (hopper-insertable; config `maxInsertedFossilItems` 2); the tank holds liquid organic material (hopper-fillable, comparator-readable) and needs a total value of 64 from items worth 1 (seeds, paper), 2 (wheat, berries, saplings), 4 (bread, carrot, bone meal, cooked meat), 8 (egg, raw meat, leather, pumpkin), 16 (cake, hay bale, fish buckets), 32 (golden apple, ghast tear), 64 (nautilus shell, sniffer egg, max revive) or 256 (enchanted golden apple, nether star, dragon egg); revival takes 12 minutes; the finished embryo is released as a wild Pokémon by breaking the tank or claimed with a Poké Ball; other players are locked out of claiming for an unstated time; fossils give a 1/20 alpha chance.
