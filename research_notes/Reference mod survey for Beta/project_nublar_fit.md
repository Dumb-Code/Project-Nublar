Scope: the local repository only, branch `kash's-slop` at commit 0c97bde plus the uncommitted working tree (git status on 2026-10-10: 19 modified files, 29 new classes under `entity/ai/behaviour/social`, 9 under `entity/dinosaur/animation`, tests and tools). Read-only; nothing was built or run.

Labels: `[v]` verified in source at the cited lines; `[inf]` inference from the cited source; `[doc]` taken from a docs file. Module keys B00 to B27 follow `docs/project-plan.md`; P2 = the port; "post-Beta" = outside the plan.

Cost assumptions used for every estimate (orders of magnitude, from the design doc's own assumptions at `docs/dinosaur-hitboxes-and-movement-design.md:767-772` and common JVM figures): 30 ns per block-state read, about 3 µs per small `noCollision` query, about 20 ns per hash-map lookup, 50 ms per server tick at 20 TPS, one `AABB` or `Vec3` allocation about 30 bytes.

## Key question 1: per-tick and per-frame hot paths in the current code

### Takeaway
The server-side cost today is dominated by three per-dinosaur block scans (about 147k block reads per animal per 20 ticks, all on the same tick for animals spawned together), the carnivore target search that ray-marches blocks per candidate per tick, the fence pole tick and fence `entityInside`, and machines that send a full block-entity update packet every tick while active. The client cost is dominated by the colour-layer system, which re-renders the whole GeckoLib model 3 to 20 times per animal per frame and allocates several objects per layer per frame. The uncommitted herd layer is instrumented and budgeted (spec: under 1 ms average for 20 animals) and is the only subsystem designed with a per-tick cost cap.

## Key question 6: tests and tooling

### Takeaway
The committed tree has no tests; the uncommitted tree has 26 JUnit-style unit test classes (371 `@Test`) that run only through a hand-written stand-in because Gradle declares no test dependency, plus 14 Forge-only GameTests with six structure templates. A MultiLoader-fitting layout needs JUnit on `:common:test` through `buildSrc`, GameTest classes in `common` with per-loader registration glue, and structure NBTs moved to common resources.
