## Key question 1: Naturalist — how animals sleep, graze, hunt, hide, flee, fear, behave as babies, get variants; what is data-driven; GeckoLib use and cost; spawn injection; SmartBrainLib candidates

### Takeaway
Naturalist 26.2 is a goal-based (vanilla `Goal`/`GoalSelector`) mod whose behaviour is mostly hard-coded per species, with prey lists, tempt foods, egg-laying blocks, biome spawns and texture variants moved into datapack tags and a per-species synced datapack registry. Between 1.20.1 and 26.2 it dropped GeckoLib entirely for vanilla keyframe `AnimationDefinition`s plus a small client-side blend-state class, and it keeps vanilla compatibility by additive `@Inject` mixins only. Several of its tiny goal classes (sleep, hide, hunt cooldown, baby panic, adults-guard-young, distanced follow, stalk, charge) are one-to-one candidates for SmartBrainLib behaviours.

## Key question 2: cosy-critters — ambient behaviours, how it keeps many small critters cheap, GeckoLib or vanilla models

### Takeaway
cosy-critters is a client-only mod whose "critters" are particles, not entities: birds, moths, spiders and an easter-egg Hat Man are `Particle` subclasses spawned from client hooks (random block animation ticks, cobweb animation ticks, end-of-client-tick), capped by hard counters (50 birds, 8 moths, 16 spiders), with no server state, no network traffic, no saving and no GeckoLib or entity models.

### Inferences
- [inf] Cost model: zero server work; client work is O(birds^2) distance checks per tick (50^2 = 2500) plus one 8-block raycast per flying bird and one entity AABB query per perched bird every 20 ticks; spiders cost 1-3 short raycasts per tick. There is no tick skipping; cheapness comes from the hard caps, from being particles (no tracking, no saving, no sync) and from distance-based removal.
- [inf] Mapping: non-dinosaur ambient animals are out of Beta scope, so this is post-Beta (Release 1 dressing). Two patterns are reusable now: (a) the 20-tick "react to nearby entities" interval and perch-block-changed check as a cheap B19 detection cadence; (b) the boids weights (alignment 0.05, cohesion 0.001, separation 0.01, range 20, separation 2) as a starting point for B26 herd travel steering constants, with the caveat that these were tuned for weightless particles, not pathfinding mobs.
- [inf] Vanilla-feel: the mod never changes gameplay; its mixins touch only client classes, so it cannot conflict with server-side mob AI mods.

### Gaps
- No performance figures are published; the Modrinth page "makes no performance claims".
- Spawn rates in absolute terms depend on vanilla's `doAnimateTick` sampling (not read here).
- The Forge/NeoForge entrypoints were not read; the 1.20.1 Forge path has a custom particle construction workaround noted in `Util` but not examined.

## Key question 4: Friends and Foes — multiloader structure, vanilla-system integration (villages, raids, spawning, tags, world gen, advancements), config, mixins, 26.x state and build, vanilla-feel rules

### Takeaway
Friends and Foes (master, 2026-10-09) builds ten Minecraft versions from one source tree with Stonecutter plus home-grown `buildSrc` convention plugins (no Architectury since 1.20.1), isolates loaders behind a tiny internal event bus and `ServiceLoader` platform interfaces, drives all mob AI with vanilla `Brain` activities and memories, and integrates with vanilla systems through about 49 common MixinExtras-style mixins (wrap/modify, not overwrite), enum extensions for custom spawn categories and raider types, tag-driven spawns with per-mob config weights, and template-pool injection for villages.

### Inferences
- [inf] Vanilla-feel rules evidenced by the code that transfer to a dinosaur mod: (1) build AI from vanilla Brain primitives and declarative memory conditions (Nublar: SmartBrainLib equivalents) rather than per-tick polling; (2) every mob and every spawn has an enable switch and configurable weight/group size (Nublar B00 TOML); (3) prefer `WrapMethod`/`ModifyArg`/`ModifyVariable` over cancelling injections, and gate optional mixins by class presence; (4) use vanilla data channels (biome tags, template pools, raider wave arrays, POI types) instead of replacing vanilla systems; (5) separate spawn categories so new creatures do not eat the vanilla CREATURE cap; (6) ship game tests for lifecycle features (eggs hatching, constructs building); (7) datafixers when renaming saved entities.
- [inf] For Nublar's module map: Tuff Golem sleep = B17 sleep with a "sleep cooldown" memory (6000-8000 ticks) and a bounded sleep duration (6000-12000); Barnacle hide = B19 hide with spot memory and drift tolerance 2.5; Glare/Penguin avoid = B19 flee with a sensor-written avoid memory expiring in 5-10 s and flee distance 16 at 1.25-1.4 speed; Crab/Penguin egg breeding = B18 nest and clutch (has-egg flag, both parents' age set to 6000 as the breed cooldown); custom spawn categories and the event-bus multiloader pattern = B00/B25 infrastructure (Nublar uses Architectury API instead, but the ServiceLoader + internal-event approach shows what Architectury replaces).
- [inf] Perf: Brain-based mobs do their expensive scans inside sensors (vanilla sensors run on a 20-tick scan rate by default, as the `Sensor` base class implies) and keep per-tick work to activity selection plus the running behaviour; this is the same cost profile SmartBrainLib gives Nublar. - [inf] 26.x support state: master builds for 26.1.2, 26.2 and 26.3 (NeoForge 26.3 beta) with Java 25; Trinkets/Curios integration is absent on 26.x; the project is the most current of the four for Nublar's 26.2 target.

### Inferences
- [inf] For the 20 TPS with 100 dinosaurs target, the per-tick AABB scans found in Naturalist (leader scan, item scans, avoid goals, follow-parent scans) are the main things to redesign: run them in SmartBrainLib sensors at 10-20 tick intervals and share results through memories, as FAF does with vanilla sensors.
- [inf] None of the four mods implements stamina-limited chases, scent trails, dominance contests, or a probabilistic detection chance by distance; those B17/B18/B19 items have no reference implementation here and need Nublar's own design.

### Gaps
- No mod here implements carcass entities, scent trails, stamina, dominance ranks or sound-based detection; the survey cannot supply numbers for those Nublar features.
- No runtime profiling was possible (clones were read only), so performance ratings are static-analysis judgements, not measurements.
