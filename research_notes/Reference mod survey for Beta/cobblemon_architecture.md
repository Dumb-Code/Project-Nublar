## Q1. Species data pipeline: species, forms, variants, spawn pools, assets, client sync

### Takeaway
Species are Gson-deserialised JSON (`data/cobblemon/species/<gen>/<name>.json`) loaded once per server by a generic `JsonDataRegistry` reload listener, patched by `species_additions`, indexed in hash maps, and pushed to each client at login as one full "registry sync" packet decoded on the network thread; models, textures and animations are bound to a species on the client by a separate `resolvers` JSON that maps the entity's synced `aspects` set to poser, model, texture and layers.

### Inferences
- Gson, not DFU Codecs, is used for all datapack records (Codecs appear only for `Pokemon` instance persistence). Gson ignores unknown keys by default and Cobblemon registers no "strict" adapter, so unknown fields are silently dropped; Nublar's "unknown fields fail loudly" needs a Codec (`RecordCodecBuilder` with `.strictOptionalField` style) or a post-parse key check. [inf]
- Cobblemon pays for data-driven depth with a very large adapter set (about 45 type adapters on one Gson). Nublar's six-species `SpeciesData` record needs none of that: one Codec per record and one reload listener. [inf]
- The "aspects" set is the single most reusable idea here: a small string set, synced once, that drives form, model, texture, layers and MoLang. Nublar's B09 colour genes and morphs can become aspects (`melanistic`, `albino`, `skin:jungle`) and the renderer resolves assets from them. [inf]

### Gaps
- Exact behaviour of a malformed species file at startup (crash vs. skip) was not traced past the `ExecutionException` in `JsonDataRegistry.parse`.
- The `spawn_pool_world` registry's reloadable flag is set inside `CobblemonSpawnPools.load()`, which I did not read.

## Q2. Breeding and genetics: IVs, natures, abilities, egg groups, shiny odds, inheritance

### Takeaway
In `main` (1.8.2) genetics is per-instance rolled state (IVs 0-31, nature, ability from a priority pool, gender from `maleRatio`, shiny at 1/8192, intrinsic size 0.95-1.05) with no breeding; breeding exists only on the `1.21.1-breeding` branch as an ordered, MoLang-scriptable rule pipeline (mother → species → form → IVs → moves → shiny → misc) with a compatibility roll and an egg-cycle-based cooldown, plus block-tag-driven wild nests.

## Q4. Entities at scale: tick cost, brain and sensors, spawning and despawning, culling, LOD, animation cost

## Q5. Networking: registry, codecs, validation, entity sync, small entity data

### Takeaway
All packets implement one `NetworkPacket` interface (a `CustomPacketPayload` with `encode`/decoder and convenience senders), are declared once in two lists of `PacketRegisterInfo(id, decoder, handler)` in common code, and are registered by thin Fabric and NeoForge managers; server handlers validate by re-deriving state from the player (PC link, controlling passenger) and comparing ids, while client state is kept current by small per-field update packets keyed by (store UUID, Pokémon UUID).

### Inferences
- Nublar's hardest target (20 TPS with 100 persistent animals) is one Cobblemon never has to meet, because Cobblemon caps wild density at about one Pokémon per chunk and despawns the rest; the budget must therefore come from B17's sensor intervals, B16's change-driven attribute updates and B25's profiling, not from spawn control.
