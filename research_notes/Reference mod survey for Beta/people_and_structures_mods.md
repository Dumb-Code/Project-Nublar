# People-and-structure mods for Project Nublar: Minecraft Comes Alive, Guard Villagers, Better Villages, Illager Invasion

Scope: how four open-source mods implement NPC AI and memory, villager professions, guard and patrol behaviour, raid and illager injection, and structure worldgen; how they stay performant and vanilla-compatible; what Project Nublar (Beta modules B00 to B27) can reimplement independently. Nothing below is code; every mechanism is described in words and numbered steps so it can be re-derived.

Labels: **[v]** verified in source at the stated commit (path and lines given); **[inf]** inference; **[doc]** from README, wiki, Modrinth or GitHub pages. Perf ratings: **low** (event-driven or interval ≥ 200 ticks, no scans), **medium** (per-tick cheap work or interval scans with a radius), **high** (per-tick entity or block scans, unbounded allocations). Module keys follow docs/project-plan.md (B00 config and species data; B13 recipes and progression; B17 needs; B18 social life; B19 player interaction and detection; B21 digsites, paleontologists, Paleo-Illagers and maps; B25 performance pass; P2 port).

## MCA: how it models villager memory, relationships, moods, schedules and dialogue

### Takeaway
MCA keeps a tiny per-player memory record (hearts, interaction fatigue, dialogue type, last-seen day) inside one NBT compound on the villager, a single clamped mood integer mapped onto seven mood bands, a registry of personalities and traits, family and marriage data in level saved-data, and schedules as vanilla brain activities (26.2: `EnvironmentAttribute<Activity>`); dialogue is a data-driven question/answer graph with weighted outcomes evaluated server-side.

### Cited Findings
- **Per-player memory record.** Effect: each villager remembers each player separately (relationship hearts, how tired it is of talking to you, which dialogue tone it uses, the last day it saw you). Mechanism: (1) a `Memories` object holds `playerUUID`, `hearts` (int), `interactionFatigue` (int), `dialogueType` (enum), `lastSeen` (long, stored as game time / 24000 = day); (2) every setter writes back through `brain.updateMemories(this)`; (3) serialised to a small compound (`playerUUID`, `hearts`, `interactionFatigue`, `dialogueType` ordinal, `lastSeen`). Perf: low per record, but see sync notes. Module: B19 (`PLAYER_REPUTATION`), B17 (memory of needs can reuse the same shape). Vanilla feel: extends vanilla gossip idea; no conflict. [v] [Memories.java L12-26, L52-55, L93-103](https://github.com/Luke100000/minecraft-comes-alive/blob/2de0738ecabf262865d1aba5f94fa0e49d02d07b/common/src/main/java/net/conczin/mca/entity/ai/Memories.java#L12-L103)
- **Memory container is one synced compound.** Mechanism: `VillagerBrain` declares tracked parameters `Memories` (CompoundTag keyed by player UUID string), `Personality` (Identifier), `Mood` (int), `MoveState`, `ActiveChore`, `ChoreAssigningPlayer` (Optional UUID), `IsPanicking`, `WearArmor`; `updateMemories` copies the whole compound, replaces one player's entry and re-sets the tracked value; `getMemories()` re-parses every entry into fresh objects on each call; `getMemoriesForPlayer` creates a record on first contact. Perf: medium; each hearts change allocates a copy of the full compound and re-syncs it to all tracking clients. Module: B19. [v] [VillagerBrain.java L36-43, L151-179](https://github.com/Luke100000/minecraft-comes-alive/blob/2de0738ecabf262865d1aba5f94fa0e49d02d07b/common/src/main/java/net/conczin/mca/entity/ai/brain/VillagerBrain.java#L36-L179)
- **Hearts arithmetic.** (1) `rewardHearts`: zero is ignored; positive broadcasts a happy entity event, negative a sad one and the SENSITIVE personality doubles the loss; fatigue += 1; hearts += value; an advancement criterion fires; mood += hearts. (2) Being hit by a player: `trustIssues = (1 - health/maxHealth * 0.75) * (3 + 2 * damage)`, subtracted from that player's hearts; chat lines are rate-limited by a 100-tick cooldown and a 40-tick `lastHit` gate. (3) Seeing a villager murdered by a player: -20 hearts for every villager within 32 blocks. Module: B19 reputation, B18 group reaction to a killing. [v] [VillagerBrain.java L307-330](https://github.com/Luke100000/minecraft-comes-alive/blob/2de0738ecabf262865d1aba5f94fa0e49d02d07b/common/src/main/java/net/conczin/mca/entity/ai/brain/VillagerBrain.java#L307-L330); [VillagerEntityMCA.java L672-780](https://github.com/Luke100000/minecraft-comes-alive/blob/2de0738ecabf262865d1aba5f94fa0e49d02d07b/common/src/main/java/net/conczin/mca/entity/VillagerEntityMCA.java#L672-L780); [Relationship.java L180-191](https://github.com/Luke100000/minecraft-comes-alive/blob/2de0738ecabf262865d1aba5f94fa0e49d02d07b/common/src/main/java/net/conczin/mca/entity/ai/Relationship.java#L180-L191)
- **Interaction fatigue decay.** Every `interactionFatigueCooldown` ticks (default 4800 = 4 minutes) the brain iterates all memory entries and decrements any fatigue > 0 by 1. Perf: medium at that instant (parses every record), amortised low. Module: B19 (anti-spam on taming/interaction). [v] [VillagerBrain.java L95-107](https://github.com/Luke100000/minecraft-comes-alive/blob/2de0738ecabf262865d1aba5f94fa0e49d02d07b/common/src/main/java/net/conczin/mca/entity/ai/brain/VillagerBrain.java#L95-L107); [Config.java L327](https://github.com/Luke100000/minecraft-comes-alive/blob/2de0738ecabf262865d1aba5f94fa0e49d02d07b/common/src/main/java/net/conczin/mca/Config.java#L327)
- **Mood model.** Effect: villager shows particles, sounds and chat tone by mood. Mechanism: (1) one int clamped to [-15, 15]; (2) seven bands depressed, sad, unhappy, passive, fine, happy, overjoyed, index = (mood + 15) * 7 / 30 clamped; (3) bands carry a sound interval (depressed 4, sad 8, overjoyed 8 ticks), particle interval (20 or 50 ticks, 50% roll), chat colour and a "cheer-up" building name (inn, music_store); (4) twice a day (`tickCount % 12000`) the mood is nudged by `random(-3..3) - round(mood/12)` so it regresses to neutral; (5) a death nearby applies `-5 * proximityAmplifier`. Perf: low. Module: B17 stress as a single clamped int with bands is the same shape. Vanilla feel: additive. ## Illager Invasion 26.2.x: new illagers and their AI, raid and patrol injection, structures, and the 26.2 project layout

### Takeaway
Illager Invasion adds ten illagers and one summon with vanilla goal-selector AI built from `SpellcasterIllager`/`AbstractIllager` and fixed cooldown integers; it joins vanilla raids by adding constants to the `Raid.RaiderType` enum (NeoForge `enumextensions.json`, Fabric enum mixin) with per-wave count arrays that a server config can zero; it adds five jigsaw structures entirely through `RegistrySetBuilder` datagen (structure, structure set, template pools, processor lists) with mob placement by one-template "mobs/<name>" sub-pools and by a data-marker processor injected into vanilla woodland mansion pieces; its Gradle layout (Fuzs multiloader convention plugins, `metadata.json`, mixins declared in Gradle, Puzzles Lib abstractions) is a compact 26.2 Fabric + NeoForge reference.

- Paleo-Illager site = buried or surface jigsaw with a `spawn_overrides.monster` list of the Paleo-Illager type (weight 3) and vanilla pillagers, so the site stays hostile until cleared; machines and fossils as loot tables `chests/paleo_illager_*`. [inf]
- The Paleo-Illager entity itself should be the smallest possible subclass of `AbstractIllager` with the common skeleton above and a retextured vindicator model (B24 flag); raid participation can be added later with the enum-extension recipe if wanted. [inf]
- Illager Invasion's build confirms the 26.2 toolchain shape Nublar is targeting (Fabric + NeoForge, Common module, access widener, Forge Config API Port on Fabric); its mixin-list-in-Gradle and `metadata.json` conventions are plugin-specific and need Fuzs' plugins, so Nublar should mirror MCA's buildSrc approach instead unless it adopts those plugins. [inf]

### Gaps
- Fuzs' convention plugin sources (how it generates `fabric.mod.json`, `neoforge.mods.toml`, mixin JSON and sets the Java toolchain) are published only as Maven artifacts; not read.
- `EnchantToolUtil`, `TeleportUtil`, `FireworksShootingHelper`, projectiles and the Imbuing Table were not read (out of scope).

### Inferences
- The only mechanism in these four mods that requires a mixin into vanilla *runtime* AI is MCA's villager replacement; everything Nublar needs for B19/B21 can be done with registries, data, events and (for raids) enum extension, which keeps the mixin count low and loader parity easy. [inf]
- None of the four mods implements a true per-tick time budget; all rely on intervals and event-driven work, which supports Nublar's B25 plan of an interval audit plus profiling rather than a budget scheduler. [inf]

### Gaps
- No published profiling data exists for any of the four mods; the perf ratings above are structural (what runs when), not measured.
- Better Villages' actual mechanism remains unverified; its row is marked as inferred.
