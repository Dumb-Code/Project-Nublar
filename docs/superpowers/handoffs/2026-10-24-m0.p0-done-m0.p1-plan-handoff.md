## Rules that hold

Spec over code. No stand-ins. Every tune-in-playtest number is a config value or "not set". Game time for timers; server-owned animation state; packets validate on the server. Libraries first. Simple, light, adversarial self-review, human-continuable. Design answers go in the docs, never in code or game data, unless the lead asks. A design gap gets the smallest version behind a config key, a "Decisions for the lead" line and a register row. Headed client for anything the lead judges by eye; headless GameTests only for pass/fail records.
