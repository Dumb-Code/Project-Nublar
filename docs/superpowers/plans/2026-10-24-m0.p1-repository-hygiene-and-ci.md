# M0.P1 Repository Hygiene and CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A repository a new contributor can build, run and test from the README alone, with the unit tests on `./gradlew :common:test`, the GameTests in `common` with one holder per loader, CI that builds both loaders on every push and pull request, and the two reference documents the later packages cite (`docs/config-reference.md`, `docs/performance-baseline.md`).

**Architecture:** Nine small tasks on branch `m0.p1/repo-hygiene` from `integration/1.20.1` at the PR #66 merge commit `622ef2c`. The unit tests already live in `common/src/test/java`; this package gives them a real JUnit 5 runtime under Gradle and deletes the stand-in runner. The 16 GameTest bodies move to `common` as plain static methods; a Forge holder and a Fabric holder carry the loader annotations and delegate one line each, because Forge reads its `@GameTestHolder` from the declaring class and Fabric registers through an entrypoint. CI is one GitHub Actions workflow.

**Tech Stack:** Gradle 8.14.4, Java 17, ModDevGradle legacyforge 2.0.77, fabric-loom 1.9, JUnit Jupiter 5.10.2, GitHub Actions (`actions/checkout@v4`, `actions/setup-java@v4`, `gradle/actions/setup-gradle@v4`, `actions/upload-artifact@v4`).

**Spec:** `docs/plan/engineering-backlog.md` section "M0.P1: Repository hygiene and CI" (lines 342 to 390), "How to use this plan" (161 to 245) and "Definition of done" (203 to 218); `docs/codebase-analysis.md` section 3.5.
