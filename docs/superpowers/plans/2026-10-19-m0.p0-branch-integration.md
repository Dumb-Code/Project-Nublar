# M0.P0 Branch Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One 1.20.1 build on branch `integration/1.20.1` that holds the machine chain, the reworked fences, the committed herd work and a ported fossil design, and that compiles on Forge and Fabric.

**Architecture:** The work branch starts from `kash's-slop` (1.20.1-ai plus the herd commit 582fbb0 and the plan docs). It builds and tests the unbuilt P12c herd code, merges `rft/adversing` (package moves, the `nublar-gui` module, the fence rework) and resolves the 11 content conflicts and 37 relocations by hand, then ports the fossil design from `fossils-1.20.1` file by file (never by merge) with the two worldgen bugs fixed under unit tests. Every in-game check runs in the headed Forge client and the lead drives it.

**Tech Stack:** Java 17, Minecraft 1.20.1, Forge 47.2.30 and Fabric 0.16.9 through ModDevGradle 2.0.77 (legacyforge) and fabric-loom, Architectury 9.2.14 registration, Forge Config API Port 8.0.0 (`ForgeConfigSpec` on both loaders), GeckoLib 4.7.3, SmartBrainLib 1.15. Unit tests run through `tools/junit-standin/run.sh` (JUnit 5 API stubs, no Gradle test task until M0.P1).

**Spec:** `docs/plan/engineering-backlog.md` section "M0.P0: Branch integration" (lines 282 to 340) and "How to use this plan" (161 to 245); `docs/codebase-analysis.md` sections 2.3, 2.4, 2.6 and 3.4; `docs/superpowers/handoffs/2026-10-19-beta-plan-implementation-handoff.md`; the herd ledger `.superpowers/sdd/2026-10-08-herd-movement-redesign/progress.md` (P12c lines) and `p12-spec.md` section P12c.

## Global Constraints

- Branch: all work on `m0.p0/branch-integration`, created from `kash's-slop`. The PR targets `integration/1.20.1`, created from `1.20.1-ai` (4244f62). Never take a file from the frozen worktree `.claude/worktrees/herd-leader-sample`.
- The herd work comes from commit `582fbb0` only. Commit `4e90174` and the three later commits are docs.
- Order: 1.20.1-ai, then P12c build and test, then `rft/adversing` by `git merge -X find-renames=30%`, then the fossil design by copy. `fossils-1.20.1` is never merged.
- Until the lead decides on P12c (D269), the herd acceptance baseline is the P13 state (playtest 6).
- One commit per task with a conventional prefix (`feat:`, `fix:`, `test:`, `docs:`, `refactor:`, `chore:`, `build:`, `merge:`).
- Spec over code: work-in-progress code proves nothing. A requirement is met only when its acceptance check passes.
- No stand-ins: a clip, sound or texture from another species counts as missing. M0.P0 adds no art of its own; it copies the fossil overlay art that `fossils-1.20.1` already holds.
- Every "tune in playtest" number is a config value. Never invent a number: write "not set" and add a register row. M0.P0 copies the config defaults of `fossils-1.20.1` unchanged and lists them under "Config keys".
- Game time for every timer. Server-owned animation state. Packets validate on the server. (M0.P0 adds no timer, animation or packet.)
- Code quality: simple, light, adversarial self-review, and a human can continue from where you stopped (Javadoc, package note, tests that explain intent). No debug output, no TODO without an issue number, no dead code added.
- Design answers go in the docs, never in code or game data, unless the lead asks for code. A design gap gets the smallest version behind a config key, a line under "Decisions for the lead" in the PR, and a register row.
- In-game checks: launch `./gradlew :forge:runClient` (headed) and hand the lead exact steps. Never run `runGameTestServer` or any headless game run. Each GameTest is its own `/test run` command.
- Both loaders must compile before any behaviour work. Fabric parity is M0.P2; M0.P0 must not make Fabric worse than `rft/adversing` leaves it (Fabric compiles there; the client has no client entry point).
- Acceptance (backlog): `./gradlew build` passes for `common`, `forge`, `fabric` and `nublar-gui`; the Forge client runs fossil to hatched animal, fence power/hurt/break/repair, and a Gallimimus herd as on `kash's-slop`; the Fabric client reaches the title screen; no `hs_err_*`, `forge/dataRun/**`, `common/src/generated/resources/.cache/**` or `.ai/` file is in the tree.

## Review Focus

1. A fossil vein whose rolled species or piece has no registered block (a config entry for a species without a `FossilCollection`, or a piece name that no block of that species carries) must place nothing and never throw during chunk generation. Pinned by `FossilRollsTest.zeroTotalOrEmptyListIsRejected` (Task 9) and by the `pickSpecies` empty-list rule in Task 11.
2. A fossil block placed by hand with a quality other than Common (creative tab, or `/setblock ... [quality=pristine]`) must drop a fossil of that quality: the loot function reads the block state, not the block. Pinned by the in-game step in Task 13 (place a Pristine item, mine it, read the tooltip).
3. A fence wire built north to south (same x on both posts) must order its neighbours the same way as an east-west wire, or broken wires render mirrored on one axis only. Pinned by `ConnectionOrderingTest` cases three and four (Task 6).
4. An item saved before this PR with quality `none` or piece `rex_skull` must keep a readable name and tooltip, not crash the inventory. Pinned by `QualityTest.unknownNameIsNull`, `FossilPiecesTest.unknownNameIsNull` and the null guard in `FossilItem.getName` (Task 10).
5. A rarity modifier of 0 or 1 in the TOML must mean "never" and "always": the old test `nextDouble() < 1.0 / chance` made every value at or below 1 mean "always". Pinned by `FossilRollsTest.rarityPassesOnlyBelowTheChance` (Task 9).

## Decisions for the lead (also go into the PR)

Each line is a choice this plan makes where the backlog or the handoff leaves one open. The task that implements it is in brackets.

- D-a. Branch layout: `integration/1.20.1` is the PR base and gets one commit (the junk removal). `m0.p0/branch-integration` starts from `kash's-slop`, so the plan docs and the herd commit travel with it. - D-c. Fence `Connection`: the rft sites pass `previous` as the neighbour toward `from` and `next` as the neighbour toward `to`, and the constructor already canonicalises both with the ends. The leftover `next == this.compared < 0` selector in `brokenSide` undoes that for one orientation. The fix is in `brokenSide`, not at the sites. Wires saved before `rft/adversing` (built by the old sites) keep the reversed order and may render their broken halves mirrored; no save migration. [Task 6]
- D-d. Fossil blocks exist for Tyrannosaurus only (27 blocks, as on `fossils-1.20.1`). The Triceratops collection of `1.20.1-ai` (455 blocks, no art) goes. F1.1 adds every species with the real design. [Task 10]
- D-e. Drops stay on loot tables: `FossilItemFunction` reads the quality from the block state, and Silk Touch drops the ore item of that quality. The `getDrops` override of `fossils-1.20.1` is not copied (it ignored Silk Touch and Fortune, which F1.1 needs). Fortune is F1.1. [Task 10]
- D-f. The DNA yield lookup in `DNAData.getDnaPercentage` is restored from `FossilsConfig` (the line `fossils-1.20.1` enabled), because the M0 gate hatches an animal from a mined fossil and a 0 % fossil cannot reach the sequencing threshold. [Task 10]
- D-g. `FossilsConfig` (TOML through `ForgeConfigSpec`) is copied and registered on both loaders. The datapack JSON under `R/data/projectnublar/config/fossils/` and `FossilConfigReloadListener` stay untouched; M0.B00 settles the format and removes one of the two. [Task 10]
- D-h. Fossil block items: four `FossilBlockItem`s per block. The Common one is registered under the block id, the other three under `{quality}_{blockId}`. [Task 10]
- D-i. The old overlay textures that no model uses after the port (`fossil_overlay/common/*.png`, `fossil_overlay/triceratops/**`, `fossil_overlay/tyrannosaurus_rex/{fragmented_skull,fresh_skull,rex_skull}.png`) stay in the tree. The Art list owns their fate. [Task 12]
- D-j. The dedicated server is not run for this package: the Forge entry point loads the client-only `ClientLevel` and crashes the server today (analysis 6.4). Recorded in the PR; the fix belongs to M0.P2. [Task 15]
- D-k. A fossil ore position whose rolled piece has no target block is skipped (nothing placed) instead of falling back to Tyrannosaurus. [Task 11]

- Produces: the rule "`getNext()` is the neighbour on the `getTo()` side, and `brokenSide(world, true)` reads that neighbour", for every wire orientation.

Why: the renderer draws the "next" half of a wire toward `getTo()` (`in[END]` comes from the clip toward `to`).
